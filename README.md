# Голосовой интерфейс к Claude Code

Разговор вместо печати — в обе стороны.

- **Слух:** диктовка вместо набора промптов. Микрофон → Groq Whisper → чистый текст
  в поле ввода. Работает и с микрофоном ноутбука, и с Bluetooth-гарнитурой.
- **Голос:** Claude говорит вслух и может задать вопрос, на который вы отвечаете
  голосом. ElevenLabs с откатом на локальный Piper.

Одна реплика ≈ **2 секунды**: 1.2 с распознавание + 0.8 с редактура.

> Интерфейс, подсказки и редактура рассчитаны на **русскую речь**. Для другого языка
> меняются `language` в `config.json`, промпт нормализации в `voice_core.py` и голос
> Piper. *(The tool is built around Russian speech; other languages need config and
> prompt changes.)*

## Что понадобится

| | Зачем | Стоимость |
|---|---|---|
| Windows 10/11 | лампочка `CapsLock` и глобальные хоткеи — через WinAPI | — |
| Python 3.10+ | всё написано на нём | — |
| [Claude Code](https://claude.com/claude-code) | ради него всё и затевалось | — |
| Ключ [Groq](https://console.groq.com/keys) | распознавание речи (Whisper) и редактура | бесплатный тариф |
| Ключ [ElevenLabs](https://elevenlabs.io) | живой голос ответов — **необязательно** | 10k символов/мес бесплатно |

Без ключа ElevenLabs всё работает: озвучка падает на локальный Piper, который
не требует ни сети, ни денег.

## Установка

```cmd
python install.py
```

Ставит зависимости, качает голос Piper (63 МБ, в репозитории его нет) и раскладывает
в `~/.claude/` скилл `talk` и слэш-команду `/voice`, подставляя путь к этому каталогу.
Прежние версии этих файлов сохраняются рядом как `*.bak`.

Дальше — два шага вручную:

1. **Ключ.** Создайте рядом со скриптами файл `.env`:

   ```
   GROQ_API_KEY=gsk_...
   ELEVENLABS_API_KEY=sk_...     # необязательно
   ```

   Файл ищется в трёх местах по порядку: переменная окружения `VOICE_KEYS_FILE`,
   затем `.env` рядом со скриптами, затем `keys.local` на три уровня выше — так
   ключи можно держать общими на все проекты в рабочем каталоге Claude Code.

2. **Микрофон.** Скопируйте `config.example.json` в `config.json` и впишите свой:

   ```cmd
   python voice_once.py --devices
   ```

   В `input_device_preferences` идут **короткие подстроки** имён, от желанного
   к запасным. Короткие намеренно: Windows MME обрезает имена до 31 символа,
   и полное «HUAWEI FreeBuds 6i» промахивается мимо «…(HUAWEI FreeBu».

Проверить, что всё на месте:

```cmd
python install.py --check
```

Отдельные части ставятся ключами `--deps`, `--models`, `--claude`.

## Два режима

### 1. Хоткей — везде, где есть поле ввода

```cmd
start_hotkey.cmd
```

| Клавиша | Действие |
|---|---|
| `CapsLock` | старт записи; второе нажатие — стоп |
| `Alt+X` | отменить запись, ничего не вставлять |
| `Ctrl+Alt+Q` | выключить демон |

**Почему CapsLock.** У неё есть собственная лампочка, и это единственная такая клавиша,
которую видит Windows. `Fn` не подходит принципиально: её обрабатывает контроллер
клавиатуры, до системы нажатие не доходит вовсе (проверено замером).

Лампочка горит **тогда и только тогда, когда идёт запись**. Отмена по `Alt+X`, упор
в лимит длительности и выход из демона на ходу гасят её принудительно — иначе она
осталась бы гореть над несуществующей записью.

⚠️ Обратная сторона: пока идёт диктовка, регистр физически включён. Если печатать
в это время, выйдет КАПСОМ.

Текст сам вставляется в активное окно — можно поправить руками перед Enter.
Прежнее содержимое буфера обмена восстанавливается через секунду.

**Если во время распознавания переключиться в другое окно, вставки не будет.**
Между «стоп» и вставкой проходит распознавание — на длинной диктовке несколько
секунд. Демон запоминает окно, из которого начали, и сверяет его перед тем, как
нажать `Ctrl+V`. Не совпало — текст остаётся в буфере обмена, капсула говорит
«текст в буфере — нажмите Ctrl+V». Это не сбой, а отказ вставлять вслепую: иначе
диктовка уходит туда, куда вы переключились, и пропадает.

Фокус обратно не отбирается намеренно. Вы переключились по своей воле и, может
быть, уже печатаете; не сделанная вставка чинится одним `Ctrl+V`, а нажатия,
уехавшие не в то окно, — ничем.

Полный текст каждой диктовки хранится в `_transcripts/` 30 дней. Вернуть
последнюю в буфер обмена:

```cmd
python voice_hotkey.py --last
```

Звуковые подсказки (консоли не видно): высокий сигнал — запись пошла;
двойной нисходящий — стоп; низкий длинный — ошибка; два коротких — пусто.

**Автозапуск при входе в Windows.** `Win+R` → `shell:startup` → положить туда
ярлык на `start_hotkey.cmd`. Оттуда же он и убирается.

### Чтобы инструмент был включён всегда

Ярлыка в автозагрузке хватает ровно на один случай — «компьютер перезагрузили».
Если демон остановлен на работающей машине (упал, закрыли, погасили ради тестов),
он не вернётся до следующего входа в систему, и заметить это можно только по
тому, что диктовка перестала работать.

Поэтому есть сторож — `keepalive.py`. Раз в несколько минут он стучится в порт
демона и поднимает его, если ответа нет. Задание в Планировщике создаётся так:

```cmd
schtasks /create /tn "Claude Voice Input Keepalive" ^
  /tr "\"%LOCALAPPDATA%\Programs\Python\Python312\pythonw.exe\" \"%CD%\keepalive.py\"" ^
  /sc MINUTE /mo 5 /f /it
```

Проверить, что он видит: `python keepalive.py --status`.

**Выключатель.** У инструмента, который поднимает сам себя, обязан быть видимый
способ его выключить — иначе «закрыть» его невозможно в принципе. Их два:

- **значок в области уведомлений** → «Выключить инструмент». Windows 11 прячет
  новые значки под стрелку `^` — перетащите его на панель один раз, и он будет
  на виду; заодно он показывает, что инструмент работает;
- **`stop_hotkey.cmd`** — то же самое файлом, работает всегда.

Оба создают файл `_daemon.off`, и пока он лежит, сторож демона **не** поднимает.
Включить обратно — `start_hotkey.cmd`, он этот файл убирает.

**Есть отказ, которого сторож не видит.** Он спрашивает демона по сокету, а тот
бывает жив и при этом глух: перехват клавиш отваливается сам по себе, и `CapsLock`
перестаёт до него доходить. Со стороны это выглядит так — нажимаете, ничего не
происходит, а лампочка гаснет сама (её гасит сторож лампочки, которому видно
«горит, а записи нет»). Такое демон определяет изнутри и поднимается заново; в
логе остаётся строка «перехват клавиш потерян».

### 2. Слэш-команда `/voice` — прямо в Claude Code

Наберите `/voice`, дождитесь сигнала, говорите. Запись останавливается **сама**
по паузе в 2.5 с, расшифровка сразу становится задачей.

Разница с хоткеем: `/voice` не требует второго нажатия, но и не даёт поправить
текст перед отправкой.

## Что происходит на экране и на диске

### Экранный индикатор

Во время записи появляется капсула: пульсирующая точка, таймер
`00:05 | 10:00`, название микрофона и **живая волна громкости** — единственный способ
увидеть «меня слышно» до конца записи. По нижней кромке ползёт нить лимита, на
последней пятой части она желтеет.

После стопа капсула не гаснет, а показывает, что происходит: «расшифровываю» →
«привожу в порядок» → «готово». Видно, что процесс идёт, а не завис.

**Капсула появляется всегда, когда открыт микрофон** — от хоткея, от `/voice`,
от голосового вопроса `ask.py`. Это не любезность интерфейса, а правило: запись
без видимого следа на экране недопустима. Поэтому индикатор поднимает не та или
иная обёртка, а сам код захвата — обойти его, открыв микрофон «мимо», нельзя.

Капсула прозрачна для мыши — клики проходят насквозь. Выключается ключом
`show_overlay: false` в `config.json`. Где она висит, задаётся там же:

```jsonc
"overlay_position": "top-center",   // top|bottom + left|center|right
"overlay_margin_px": 12             // отступ от края
```

Отступ считается от **рабочей области**, а не от кромки экрана, поэтому
`bottom-center` не уезжает под панель задач. Капсула выезжает со своей стороны:
верхняя — сверху, нижняя — снизу. Посмотреть вид, не запуская демона:

```bash
python overlay.py --demo 12
```

**У состояния есть срок годности.** Индикатор — отдельный процесс и переживает
того, кто его запустил, поэтому он не гасит капсулу по команде, а перестаёт ей
верить: в файле состояния лежит `expires_at`, и после него окно скрывается само.
Без этого капсула «готово» висела на экране бесконечно, если демон завершался
раньше, чем срабатывало его отложенное гашение (так и случилось 31.07). Плюс
индикатор держит именованный мьютекс — второй экземпляр поверх первого не
поднимается.

Сроков два, и разница не косметическая. Фаза записи переписывается десять раз
в секунду, ей хватает **10 секунд**; сетевые фазы пишутся разово и ждут ответа
Groq, им дано **120**. Общий длинный срок означал бы, что после жёсткого убийства
процесса капсула «идёт запись» провисит над закрытым микрофоном две минуты —
то есть соврёт ровно в ту сторону, от которой этот индикатор и заведён.

### Записи хранятся сутки

Аудио сохраняется в `_recordings/` **до** отправки в облако: обрыв сети не должен
стоить надиктованного. Прогнать сохранённую запись заново:

```bash
python voice_once.py --file _recordings\rec_20260731_201931.wav
```

Файлы старше 24 часов (`recordings_ttl_hours`) удаляются сами при следующей записи.

### Расшифровки хранятся месяц

Аудио живёт сутки, текст — дольше: он невесом, а восстанавливать его из WAV значит
идти в облако второй раз и только пока запись цела. Полный текст каждой диктовки
ложится в два места:

- `_last_transcript.txt` — последняя, перезаписывается;
- `_transcripts/ГГГГ-ММ-ДД.md` — история за день, блоками со временем и источником.

Вернуть последнюю расшифровку в буфер обмена:

```cmd
python voice_hotkey.py --last
```

Команда читает файл, а не спрашивает демона: нужна она ровно тогда, когда что-то
пошло не так, и демон может быть уже мёртв. Пишется история **после** вставки, но
независимо от её успеха — файл нужен как раз в том случае, когда вставка не удалась.

Дневные файлы старше `transcripts_ttl_days` (30) убираются при следующей записи,
весь журнал выключается `keep_transcripts: false`.

### Пишется сразу со всех микрофонов

Если в системе несколько микрофонов, запись идёт **со всех одновременно**, а в
облако уходит тот, в котором действительно слышна речь. Выбор делается после
записи, по уровню сигнала в полосе разборчивости (300–3400 Гц), а не по общей
громкости: далёкий микрофон отдаёт низкочастотный гул, который бывает громче
близкого голоса и при этом нераспознаваем.

Зачем это нужно, лучше всего объясняет случай, ради которого сделано.
К ноутбуку по Bluetooth подключены наушники — и лежат в другой комнате. Человек
говорит в ноутбук, а запись уходит на гарнитуру за стеной: профиль микрофона у
Bluetooth поднимается не при подключении, а при первом обращении к записи.
Получается диктовка «в никуда», причём расшифровка возвращает не пустоту, а
уверенную бодрую фразу — Whisper на тишине не молчит, он **досочиняет** текст.

Теперь в такой ситуации побеждает микрофон ноутбука, и происходит это без единой
настройки. Отключается в `config.json`: `"multi_source": false`; сколько
дополнительных микрофонов писать — `multi_source_max` (по умолчанию 2).

Первым в `input_device_preferences` осознанно стоит встроенный микрофон: он
всегда там же, где вы. Гарнитура пишется параллельно, и если вы говорите
**в неё**, она выиграет сравнение сама.

### Посмотреть, что вообще попало в микрофон

```bash
python diag_audio.py                    # все сохранённые записи
python diag_audio.py файл.wav --spectrum
```

```
rec_20260807_231129.wav    16.7с   0.00000     0%   -76дБ  ПУСТО — расшифровка будет выдумана
                           ▁  █▄       ▆
```

Колонка «речь» — уровень в полосе разборчивости. Ниже `0.008` расшифровывать
нечего: что бы ни вернула модель, она это додумала. Такой результат инструмент
всё равно покажет, но пометит прямо в тексте — `⚠ ТИХАЯ ЗАПИСЬ, текст мог быть
выдуман:`. Пометка стоит в начале строки намеренно: текст читают с первого слова,
а не целиком.

### Управление без клавиатуры

```bash
python voice_hotkey.py --send toggle   # старт/стоп
python voice_hotkey.py --send cancel   # отмена
python voice_hotkey.py --send quit     # выключить демон
python voice_hotkey.py --send state    # {"recording": false, "capslock": false, "busy": false}
python voice_hotkey.py --send ping     # жив ли вообще
```

Команды идут в тот же сокет `127.0.0.1:47843`, который сторожит второй экземпляр
демона. Через него же ходят автотесты — **программно «нажать» CapsLock нельзя**:
регистр переключится на живой клавиатуре, а нажатие уйдёт в активное окно.

## Голос: Claude говорит и спрашивает

```bash
python speak.py "Готово, все тесты прошли"        # сказать
python speak.py --stdin < answer.txt              # длинный текст
python speak.py --dry "текст"                     # показать, что прозвучит, молча
python ask.py "Ставим 70b или хватит 8b?"         # спросить и услышать ответ
python ask.py --options "70b|8b" "Ставим 70b или хватит 8b?"   # ответ из списка
```

`ask.py` произносит вопрос, ждёт конца собственной фразы, включает запись и печатает
распознанный ответ в stdout. Это позволяет вести диалог, не касаясь клавиатуры.

### Вопрос с вариантами ответа

`--options "а|б|в"` решает проблему, которой не видно, пока не начнёшь так работать:
спрашивающий знает список допустимых ответов, а распознавание — нет. «Машинный JSON»
приезжал как «машинен.json», и смысл приходилось восстанавливать по контексту.

Варианты идут двумя путями сразу: в подсказку Whisper (та же механика, что у
глоссария, только на один вызов) и в детерминированный матчер, который сопоставляет
услышанное со списком. Вывод — две строки:

```
ВЫБОР: JSON (точно)
ОТВЕТ: Давай, машинный JSON.
```

Уверенность бывает `точно` (все значимые слова варианта прозвучали), `похоже`
(часть слов или указание номером — «давай второй») и `не определён`. Последнее —
не сбой: на «на твоё усмотрение» матчер обязан промолчать, а не подгонять ответ
под ближайший вариант. Словоформы учитываются по общему корню («переписывать» →
«переписать целиком»), но не короче пяти букв: на четырёх «пере» одинаково
начинает «перенести» и «переписать».

`--mute` произносит вопрос молча (нужен автотестам: они не должны шуметь в наушники).

Claude вызывает это сам — через скилл `talk` (`~/.claude/skills/talk/SKILL.md`),
где описано, когда говорить, а когда молчать. Голос ценен редкостью: болтливый
ассистент выключают.

### Каскад движков

Пробуются по порядку, пока какой-то не сработает (`tts_chain` в `config.json`):

| Движок | Качество | Задержка | Лимит |
|---|---|---|---|
| **ElevenLabs** | живой голос | ~2 с | 10 000 символов/мес на ключ |
| **Piper** | ровный, произношение верное | 0.4 с | нет, работает локально |
| edge-tts | деревянный, ошибки ударений | ~2 с | нет, но нужна сеть |
| SAPI Irina | робот | мгновенно | нет, есть в Windows всегда |

Реплики длиннее `tts_premium_max_chars` (300) сразу уходят на Piper — лимита
ElevenLabs хватает примерно на 80 коротких фраз в месяц, и тратить его на длинные
пересказы незачем.

**Несколько ключей = несколько бюджетов.** Добавьте в файл ключей строки
`ELEVENLABS_API_KEY_2=…`, `_3=…` — переключение при исчерпании квоты автоматическое.
Но библиотечные голоса (все 600 русских носителей) так не открыть: это ограничение
тарифа, а не количества ключей. Подробности — `service-notes/elevenlabs.md`.

### Подбор голоса

```bash
python voice_lab.py --plan              # план прогона и расход, ничего не тратит
python voice_lab.py --stage a           # прослушать претендентов
python voice_lab.py --replay a          # переслушать из кэша, бесплатно
python voice_lab.py --stage c --voices eric,george   # сравнить по живости
```

Каждый синтез кэшируется в `_voice_samples/`, повторное прослушивание бесплатно.
`stability` (живость) — главный параметр: ниже значение, больше интонаций.
Текущий выбор: **Эрик, stability 0.3**.

## Что делается с распознанным текстом

1. **Whisper** (`whisper-large-v3-turbo`) с глоссарием — в `glossary.txt` 49 рабочих
   терминов, они подсказывают модели написание: «Айртейбл» → `Airtable`,
   «Постгрес» → `Postgres`, «Грин АПИ» → `Green API`.
2. **Редактура** (`llama-3.3-70b-versatile`) — убирает «ну/вот/короче», самоперебивы,
   ставит пунктуацию.
3. **Правка терминов** — детерминированная, уже после модели: результат не зависит
   от настроения LLM.
4. **Валидатор** — проверяет, что редактура не исказила смысл: вопрос остался вопросом,
   приказ приказом («посмотри» не стало «посмотрим»), объём не уехал вдвое.
   Нарушение → один переспрос → откат к сырой расшифровке. Лучше менее причёсанный
   текст, чем искажённый.

Глоссарий пополняется просто: одна строка = один термин в `glossary.txt`, перезапуск
не нужен. Но это **словарь того, кто диктует**, а не список всех слов проекта:
подсказка Whisper обрезается примерно на 224 токенах, и каждый лишний термин вытесняет
нужный. Условия для включения — оба сразу: слово звучит в живой речи и звучит регулярно.
Правило целиком — `CLAUDE.md` §10.

## Настройка

Всё в `config.json`. Что меняют чаще всего:

| Ключ | Смысл |
|---|---|
| `input_device_preferences` | порядок выбора микрофона по подстроке имени; первый найденный побеждает |
| `silence_stop_sec` | сколько молчать, чтобы `/voice` остановил запись (2.5) |
| `max_record_sec` | потолок для хоткея (600 с = 10 минут) |
| `auto_max_record_sec` | потолок для `/voice` (90 с) |
| `vad_factor` | во сколько раз речь должна быть громче фона (3.5) |
| `normalize` | `false` — отдавать сырую расшифровку без редактуры |
| `auto_paste` | `false` — только класть в буфер, не жать Ctrl+V |
| `show_overlay` | `false` — не показывать капсулу на экране |
| `overlay_position` | где висит капсула: `top`/`bottom` + `left`/`center`/`right` |
| `overlay_margin_px` | отступ капсулы от края рабочей области (12) |
| `keep_recordings` | `false` — не сохранять аудио в `_recordings/` |
| `recordings_ttl_hours` | сколько часов хранить записи (24) |
| `keep_transcripts` | `false` — не сохранять текст диктовок |
| `transcripts_dir` | куда складывать историю расшифровок (`_transcripts`) |
| `transcripts_ttl_days` | сколько дней хранить дневные файлы истории (30) |
| `hotkey` / `cancel_hotkey` / `quit_hotkey` | клавиши; при хоткее, отличном от `caps lock`, лампочка не трогается |

Микрофоны: `python voice_once.py --devices`.

### Про шумные места

Порог тишины **подстраивается на ходу**: фон переоценивается каждые несколько
секунд, порогов два (начать запись труднее, чем продолжить), а сверху порог ограничен
третью от громкости вашей же речи. Это чинит кафе, где фиксированный порог не
срабатывал никогда — запись шла до потолка длительности.

Если в очень громком месте `/voice` всё же не останавливается сам — пользуйтесь
хоткеем: там стоп по второму нажатию, и VAD не участвует.

## Проверка

```cmd
python tests\test_vad.py             REM VAD и шумные места, быстро, без сети — 19 проверок
python tests\test_pipeline.py        REM весь конвейер на синтезированной речи (Groq) — 24
python tests\test_acoustic.py        REM железо, демон, лампочка CapsLock — 17
python tests\test_options.py         REM выбор из вариантов + срок годности состояния — 30
python tests\test_options.py --no-net    REM только то, что не требует сети — 21
python tests\test_lamp_and_start.py  REM лампочка, отказ перехвата клавиш, старт записи — 21
python tests\test_focus_guard.py     REM вставка не уходит в чужое окно, история расшифровок — 27
python tests\test_indicator.py       REM индикатор везде, где открыт микрофон — 43
python tests\test_daemon_e2e.py      REM демон целиком через сокет (нужен свободный порт) — 13
python tests\test_keepalive.py       REM сторож демона, значок в трее, выключатель — 10
python tests\test_overlay_live.py    REM настоящее окно индикатора на экране — 8
python tests\test_source_choice.py   REM выбор микрофона и тревога «в записи нет речи» — 36
python tests\test_multi_source_live.py   REM параллельные потоки на живом железе — 9
```

`test_source_choice.py` не трогает ни микрофон, ни сеть. Его главная проверка —
что далёкий гул, который **громче** близкой речи по общей громкости, всё равно
проигрывает ей по метрике разборчивости. Без этой проверки метрика была бы
неотличима от обычного RMS: на паре «речь против тишины» они согласны обе, а
расходятся ровно в том случае, ради которого всё и сделано.

Там же зафиксированы измеренные уровни настоящих записей вместе с прочитанным
результатом их расшифровки. Записи живут сутки и в репозиторий не попадают —
числа переживают их намеренно, и порог теперь нельзя сдвинуть, не сломав тест.

`test_multi_source_live.py` **открывает настоящий микрофон** на четыре секунды.
Если второго микрофона в системе нет, дубль берётся с того же устройства через
другой звуковой API: для механики это полноценный второй поток, а совпадение
уровней служит проверкой — два потока с одного микрофона обязаны слышать одно и то же.

Отсутствие железа тесты не считают поломкой: не подключена гарнитура — проверка
не «красная», а пропущенная, и это видно отдельной строкой `ПРОПУЩЕНО`. Красный
тест из-за лежащих в сумке наушников обесценивает весь прогон: рядом с ним
перестают замечать настоящую поломку.

Фикстуры пересоздаются `tests\make_fixtures.ps1` (голос SAPI Irina). Исключение —
`answer_*.wav`: это **живые записи** живого человека, и в репозиторий они не выложены.
Синтезом их не заменить: ошибка, ради которой появился `--options` («машинный JSON» →
«машинен.json»), рождается именно на настоящем голосе, а SAPI диктует слишком чисто.
На чистом клоне эти четыре e2e-проверки пропускаются — тест говорит об этом отдельной
строкой, чтобы «зелёный» не означал «проверено».

`test_overlay_live.py` — единственный тест, который показывает окно на экране:
он спрашивает Windows, видна ли капсула, а не смотрит во внутреннее состояние.
Проверять гашение иначе бессмысленно — баг 31.07 был именно в том, что код считал
капсулу погашенной, а на экране она висела.

Тесты **молчат и не трогают клавиатуру**: звук только по флагу `--loud`, демон
управляется по сокету, а поведение лампочки проверяется на модели клавиатуры
(`test_lamp_and_start.py`). Настоящее синтетическое нажатие переключило бы регистр
человеку, который в этот момент работает за той же машиной.

**Что автотестами не проверить:** разборчивость на живом голосе. Windows вычитает
из микрофонного входа то, что сама вывела на динамики (эхоподавление), поэтому
«свои колонки → свой микрофон» даёт Whisper мусор. Проверка живым голосом — только руками.

## Куда уходит ваш голос

Инструмент открывает микрофон и отправляет звук наружу — поэтому важно, что именно
и куда.

- **В облако уходит только сама диктовка.** Аудио → Groq (Whisper) на распознавание,
  затем полученный текст → Groq (Llama) на редактуру. Больше никуда и никогда.
- **Микрофон открыт только во время записи** — от нажатия до нажатия. Резидентный
  демон держит хоткей, а не поток с микрофона.
- **Пока идёт запись, это видно:** горит лампочка `CapsLock` и висит капсула на
  экране. Инвариант «горит ⟺ пишем» поддерживается отдельным сторожем, который
  сверяет их непрерывно, а не только в начале и конце.
- **Записи остаются на диске** в `_recordings/` и удаляются через сутки
  (`recordings_ttl_hours`). Сохраняются они **до** отправки в облако: сетевой сбой
  не должен стоить надиктованной задачи. Выключается `keep_recordings: false`.
- **Текст диктовок остаётся на месяц** — `_transcripts/` и `_last_transcript.txt`.
  Это тот же голос, только буквами, и в некотором смысле уязвимее: содержимое
  ищется поиском и читается с одного взгляда. В репозиторий каталог не попадает,
  выключается `keep_transcripts: false`.
- **Ключи не печатаются** ни в лог, ни в вывод — ни при ошибках, ни при отладке.
- **Piper и SAPI работают локально.** Если убрать `eleven` из `tts_chain`, озвучка
  вообще перестанет ходить в сеть.

## Если не работает

Первым делом — `_daemon.log` рядом со скриптами: он пишется всегда, независимо от
того, как запущен демон.

| Симптом | Причина |
|---|---|
| «GROQ_API_KEY не найден» | нет ключа: `python install.py --check` покажет, где его ищут |
| «демон уже запущен (порт 47843 занят)» | демон живёт; `--send quit` или `Ctrl+Alt+Q` |
| Капсула не появляется | `show_overlay: false`, либо демон стартовал раньше, чем успел подняться индикатор — проверьте `--send state` |
| Капсула мешает вкладкам браузера | перенести: `"overlay_position": "bottom-center"` в `config.json`, перезапуск не нужен |
| CapsLock разошёлся с записью | сторож выравнивает за ~0.4 с сам; если нет — демон убит принудительно, погасите клавишей |
| CapsLock ничего не запускает, а лампочка гаснет сама | перехват клавиш отвалился: демон замечает это со второго нажатия и поднимается заново (в логе «перехват клавиш потерян»). Если и в логе тишина — `--send quit`, затем `start_hotkey.cmd` |
| Печатается КАПСОМ во время диктовки | так задумано: включённый CapsLock и есть лампочка записи |
| Первое слово обрезано | увеличить `warmup_ms` (гарнитура дольше переходит в HFP) |
| Запись не стартует | микрофон занят другим приложением; проверить `--devices` |
| Текст странно перефразирован | сработал откат валидатора — смотрите лог, там причина |
| Расшифровка не появилась в окне | за время распознавания сменился фокус: текст ждёт в буфере, жмите `Ctrl+V`. Буфер уже затёрли — `python voice_hotkey.py --last` |
| «слышит очень тихо» в логе | выбранный микрофон почти ничего не слышит; если рядом есть второй — победит он, смотрите строку «источник» в логе |
| Расшифровка бодрая, но не о том | запись была пустой, текст додуман моделью. `python diag_audio.py` покажет уровень; ниже `0.008` расшифровывать нечего |
| Голос произносит бессмыслицу | текст пришёл в чужой кодировке; проверьте через `speak.py --dry` |
| ElevenLabs молчит, звучит Piper | реплика длиннее `tts_premium_max_chars`, кончились символы или нет сети. Что именно — покажут `python speak.py --quota` и `_daemon.log` |

**Про снятую гарнитуру.** По фону это неотличимо: микрофон ноутбука в тихой комнате
шумит ровно столько же, сколько наушники, лежащие на столе (0.00002) — поэтому
предупреждение в логе остаётся предупреждением, а не запретом.

Различить их можно только по факту записи, когда человек уже говорил, — и именно
так теперь и делается: пишутся все микрофоны сразу, а в облако уходит тот, в
котором слышна речь. Вопрос «надета ли гарнитура» отвечается сам собой, вместо
того чтобы задавать его человеку заранее.

Лог демона — `_daemon.log` (пишется всегда, обрезается на 512 КБ), текущее
состояние одной строкой — `_last_run.status`.
